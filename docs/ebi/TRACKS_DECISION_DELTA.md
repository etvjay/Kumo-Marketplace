## What changed

The current BNB Tracks page materially confirms the following build order.

### P0 — mandatory main-track proof

```text
public front end
+ four equally deep categories
+ live BSC agents
+ real-time decision-useful data
+ cold-user discover → understand → activate journey
```

No architecture work may delay these gates.

### P1 — discovery truth

Primary discovery substrate:

```text
8004scan / ERC-8004
```

But registry/list/search data cannot be treated as liveness or execution proof.

Required qualification pipeline:

```text
registry candidate
→ full metadata/services
→ independent liveness
→ category qualification
→ trust/security/economic evidence
→ activation capability
```

### P2 — bounded activation

Preferred high-confidence path where supported:

```text
PreparedAction
→ refresh / drift check
→ ActivationEnvelope
→ Altana scoped session
→ ERC-8183 hire
→ Kumo Execution Pod
→ receipt
→ outcome verification
```

Altana hard qualification requires real session limits, Keystore registration, real session-key transaction, user-visible authority and revocation.

### P3 — cross-track live proof

First target:

```text
PancakeSwap LP rebalancing
```

This should be designed to generate evidence for:

- Main Rebalancing depth
- Data Quality
- Altana bounded authority
- PancakeSwap real benefit
- TermiX paired baseline

### P4 — experiment/reputation

TermiX Agent Advantage instrumentation begins before polished agents:

```text
T0 input
baseline output
agent output
time
cost
quality rubric
risk/window
actual result
```

Do not reconstruct track record retrospectively.

## Blocking experiment

Before expanding the marketplace UI, execute the four-category supply probe.

For each mandatory category classify:

```text
QUALIFIED
PARTIAL
FAILED
```

A category is `QUALIFIED` only if at least one candidate has:

```text
BSC identity
+ current metadata
+ live callable service
+ capability evidence matching category
+ sufficient decision data
+ plausible activation path
```

If any category is `FAILED`, Kumo must deploy/onboard real supply rather than fill the marketplace with weak registry matches.
